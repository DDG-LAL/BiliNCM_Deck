# Phase 2/3 回归清单

本文用于真实直播弹幕（Phase 2）和手动网易云 UI（Phase 3）的现场验证。回归前保留旧便携版作为回退，不要覆盖旧目录。

## 回归前准备

- 用主播账号扫码登录，`/api/config` 中 `biliLogin=true`、`uid>0`
- 连接直播间，`/state` 中 `bot=true`、`ncm=true`
- 网易云 2.10.13 正在运行，`9222` CDP 可用，`/api/ncm/state` 返回 `ok=true`
- 准备三个身份：主播、房管、普通观众
- 直播歌单至少 4 首，当前歌不要是最后一首
- 确认 `config.json` 权限矩阵：
  - `OrderPermission`：按需要开放普通观众点歌
  - `ToggleAcceptPermission`：建议 `MinGuardType=-1`，只允许房管/SuperUser
  - `ForceControlPermission`：建议 `MinGuardType=-1`
  - `CancelPermission`：普通观众需要能撤回自己的待播
- 启动参数建议加 `--no-browser` 时先确认页面已手动打开，或正常启动
- 未开播可以验证队列和大部分命令，但最终权限/房管标记/真实观众验证建议在开播状态下再跑一轮
- 连接日志会记录 `live_status`；`1` 才表示直播中，`0/2` 等状态可能代表未开播或轮播
- 回归期间保留 `deck.log`，不要清理

## Phase 2：真实直播弹幕

| # | 场景 | 操作 | 通过标准 |
|---|---|---|---|
| 1 | 登录/房间 | 主播账号扫码并连接房间 | `biliLogin=true`，`uid>0`，`config.json` 中 Cookie 含 `SESSDATA`，`/state` 中 bot/ncm 为 true |
| 1b | 扫码失败 | 让二维码过期或取消确认 | 状态明确显示失败/失效；不保存空 Cookie，不误报登录成功 |
| 2 | 断线重连 | 短暂断网或重启网络 | 日志出现重连，恢复后弹幕仍可用 |
| 3 | 普通点歌 | 观众 A 发“点歌 歌名” | 当前歌不被打断；新 d 在当前歌/最后 pending 后；浮层显示点歌人 |
| 4 | FIFO | A、B、C 依次点歌 | NCM 与浮层顺序均为 A/B/C |
| 4b | 同时点不同歌 | 两个观众几乎同时各点一首不同歌曲 | 两条原始弹幕都进入 `danmaku.log`；两条都有 `request` 和 `queued/moved` |
| 5 | 重复点歌 | 同一首再次点歌 | 不新增 NCM 副本；浮层不重复 |
| 6 | 已播再点 | 歌曲播完后再次点同一首 | 原副本升级为待播 d，不新增第二份 |
| 7 | 撤回待播 | 观众撤回自己的待播 | 浮层行消失；NCM 副本删除；不会复活 |
| 7b | 撤回未入队 | 点歌后引擎尚未 add 时立刻撤回 | bot/浮层取消；NCM 不应留下副本 |
| 7c | 撤回后核对 NCM | 撤回已入队待播 | `queueLen` 减少或对应 wrapper 消失，不能只消失浮层 |
| 7d | A/B 同歌撤回隔离 | A、B 点同一首，B 先撤回，A 后撤回 | B 撤回后 A 的 pending 和 NCM 副本仍在；A 也撤回后才删除 NCM |
| 8 | 撤回当前 | 普通观众撤回自己点的当前歌 | 拒绝并记录日志；当前歌不被打断 |
| 9 | 撤回当前（房管/主播） | 房管或主播撤回当前歌 | 允许；切到下一首；日志记录操作者 |
| 10 | 切歌权限 | 普通观众发“切歌/跳过” | 拒绝；当前歌不变 |
| 11 | 切歌权限（房管/主播） | 房管/主播发“切歌/跳过” | 只切一次；NCM `current.id` 必须变化；pending 不被改坏 |
| 12 | 移除 | 房管/主播发“移除 关键词” | 待播行消失；NCM 副本删除；普通观众无权限 |
| 13 | 暂停/恢复 | 房管/主播发“关闭点歌”，普通观众点歌，再发“开启点歌” | 暂停期间普通点歌被拒绝；管理命令可用；开启后恢复 |
| 13b | 普通观众关闭点歌 | 普通观众发“关闭点歌” | 权限拒绝，接受状态不变 |
| 14 | 置顶点歌/置顶 | 主播/房管发送 | 目标/新请求位于当前歌下一首；当前歌不变 |
| 14b | 普通观众置顶 | 普通观众发“置顶点歌/置顶” | 权限拒绝 |
| 14c | 主播置顶实际生效 | 主播置顶一个已在 NCM 的 pending | 当前歌不变；目标位于当前歌下一首；连续置顶以最后一次排最前 |
| 15 | 长跑 | 连续 30～60 分钟点歌/撤回/切歌 | 无重复副本、无队列漂移、无未处理异常，`deck.log` 无 ERROR 堆积 |
| 16 | 开播状态 | 分别在未开播/开播状态连接；开播后等待刷新 | `deck.log` 记录 `live_status` 变化；WS LIVE/PREPARING 或 60 秒轮询能更新；最终权限/房管/真实观众验证以开播状态为准 |
| 17 | 登录持久化 | 登录成功后重启 Deck | 自动恢复登录并连接历史房间 |
| 18 | 身份矩阵 | 主播、非主播房管、普通观众、SuperUser 非房管 | 权限符合 README 的“弹幕指令”表 |

> `移除` 是主播/房管/SuperUser 的管理清理命令；普通观众的撤回入口是 `撤回/取消`，只能撤回自己的待播。

### 直播回归观察点

- `/state`：`current`、`pending`、`pendingCount`、`updated`
- `/api/ncm/state`：`currentIndex`、`queueLen`、当前 wrapper
- `deck.log`：`request:`、`queued d:`、`promoted d:`、`moved d:`、`playing:`、`played:`、`pending d ...`、权限拒绝、`批量包已解析`
- `danmaku.log`：全部 `DANMU_MSG` 的时间、UID、用户名、身份和原始内容
- 网易云播放列表截图：确认当前歌没有被打断、pending d 没有重复

## Phase 3：手动网易云 UI

| # | 场景 | 操作 | 通过标准 |
|---|---|---|---|
| 1 | 拖动 pending | 把 pending d 拖到其他位置 | 1～2 秒内 5566 浮层顺序跟随，引擎不改回 |
| 2 | 拖到当前之前 | pending d 拖到当前歌之前 | 视为已播，浮层行消失，不复活 |
| 3 | 删除 pending | 在 NCM UI 删除待播 d | 3 次轮询内浮层行消失，不重新加回 |
| 4 | 手动插入同歌 | 在队列里再放一份同歌 | 不误判为 pending d；只认 `PendingQid` 精确匹配 |
| 5 | 删除普通歌 | 删除非 d 的普通队列项 | 浮层不应出现/消失错误，当前歌不受影响 |
| 6 | 换歌单 | 在 NCM 切换播放列表 | 旧 pending 清空；不强行回填；新歌单可继续点歌 |
| 7 | NCM 重启 | 关闭并重新启动网易云 | 页面变化后等待稳定，按 `Seq` 恢复真正缺失的 pending，不重复、不复活历史 |
| 8 | CDP 断线 | 关闭/重开 NCM 调试页 | 日志出现 `NCM state unavailable` / `available`；恢复后继续工作 |
| 9 | 并发拖拽 | 引擎 add/move 时手动拖动 | 最终顺序稳定，无重复副本 |

### 手动回归注意点

- 手动顺序优先；引擎只在自己需要 add/move 时操作，不应把主播手动调整改回去。
- 手动删除 pending 后，bot 队列里可能仍有请求；引擎应停止跟踪该 pending，而不是重新加回。
- 换歌单和 NCM 重启是不同语义：
  - 换歌单：不强行回填旧 pending
  - NCM 重启（页面 `performance.timeOrigin` 变化）：按 `Seq` 恢复真正缺失的 pending
- 如果网易云升级后 `defPlayer.MF` 或 store 结构变化，先看 `deck.log` 的 CDP 错误，再评估兼容。

## 通过标准与回退

通过标准：

- 上述直播和 NCM UI 用例全部通过
- `deck.log` 无未解释的 ERROR
- 当前歌在普通点歌/撤回待播时从未被打断
- 普通观众无法切歌或撤回当前歌
- 手动拖动/删除/换歌单不会被引擎改回或错误复活

回退：

- 停止 Deck，重新启动旧便携版
- 不修改旧 portable 的 `current\` 目录
- 新 Deck 的配置和日志保留，便于继续排查
